# Практическое занятие № 9 — Разработка приложений WPF (ADO.NET)

**Вариант 2.** Программа для приёма товара. Информация о товаре лежит в накладных в текстовом файле.
Весь товар автоматически размещается на первый свободный склад. Если места на одном складе не хватает,
товар делится по нескольким складам, и программа обязательно сообщает об этом пользователю.

## Как запустить

1. **База данных.** SQL Server Management Studio → «Создать запрос» → вставить весь файл
   `База данных Склад.sql` → **F5**. Будет создана база «Склад» с тестовыми данными.
   Запомнить имя сервера из окна входа SSMS (в лаборатории, например, `lab215-16`).
2. **Строка подключения.** Открыть `WpfApp1.sln` (Файл → Открыть → Проект или решение).
   В `WpfApp1/App.config` заменить `.\SQLEXPRESS` в `Data Source=` на имя своего сервера. Ctrl+S.
3. **Запуск.** Правой кнопкой по проекту WpfApp1 → «Назначить запускаемым проектом» → **F5**.

## Как пользоваться

1. «1. Открыть файл накладных» → выбрать файл из папки `Тестовые накладные`.
2. Проверить список товаров справа → «2. Принять товар».
3. Появится итог: куда положен каждый товар; если товар разделён по складам — строка «ВНИМАНИЕ!».
4. В таблице складов обновится загрузка; щелчок по складу показывает его содержимое.

## Проверка на разных наборах данных

Выполнять по порядку сразу после создания базы (свободно: Склад №1 — 20, №2 — 0, №3 — 300, №4 — 1000 уп.):

| Файл | Что проверяет | Ожидаемый результат |
|---|---|---|
| `1_обычный_приём.txt` | товар помещается на первый свободный склад | молоко и сахар легли на Склад №1, он заполнился |
| `2_разделение_по_складам.txt` | две накладные в одном файле, разделение | гречка → Склад №3; мука разделена: Склад №3 — 100, Склад №4 — 150 (ВНИМАНИЕ!); соль → Склад №4 |
| `1_обычный_приём.txt` ещё раз | повторный приём | «уже была принята раньше — пропущена» |
| `3_не_хватает_места.txt` | товара больше, чем места | «НЕ принята», в базе ничего не изменилось |
| `4_ошибка_в_файле.txt` | ошибка в файле | сообщение с номером строки с ошибкой |

Полностью переполненный Склад №2 пропускается всегда.

## Формат файла накладных

```
Номер: Н-101                 <- начало накладной (в файле их может быть несколько)
Дата: 29.09.2026
Поставщик: ООО «Молпром»
Молоко 3,2% 1 л; 15          <- наименование; количество упаковок
```
Пустые строки и строки с `#` пропускаются, остальные поля (например, «Товары:») игнорируются.

## Чек-лист из методички

| Требование | Как выполнено |
|---|---|
| Целостность данных | первичные и внешние ключи, `UNIQUE`, `CHECK (количество > 0)`, триггер не даёт превысить вместимость склада |
| Таблицы заполнены тестовыми данными | 4 склада, 4 товара, 2 накладные, 5 размещений |
| Работа с данными из БД | все данные читаются и пишутся через ADO.NET |
| Обработка данных запросами | занято/свободно считает представление `Загрузка_складов`, первый свободный склад — `SELECT TOP 1 … ORDER BY` |
| Обработка исключений | `try/catch` на каждом обращении к базе и чтении файла, транзакция откатывается при ошибке |
| Тестирование на разных данных | 4 тестовых файла, таблица выше |
